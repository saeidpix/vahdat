# اتوبنز وحدت — نسخه دسکتاپ مشترک تمام شعبه‌ها

## هدف
**یک فایل نصب یکسان** برای تهران، آمل، بابل، قائم‌شهر و ساری.
از Windows 7 SP1 (x86/x64) تا Windows 11 (x64) با RAM چهار گیگ.
این نسخه مبتنی بر Python 3.8 x86، Tkinter و SQLite است و برنامه را در
پنجره مستقل اجرا می‌کند: نه مرورگر، نه HTTP listener، نه Firewall rule.

> ساخت در GitHub روی Windows Server 2022 تست می‌شود. سازگاری واقعی
> با Windows 7 و 8/8.1 فقط با نصب میدانی قابل تأیید است. Windows 7
> قدیمی و فاقد به‌روزرسانی امنیتی است؛ داده و کلید آزمایشی کم‌اختیار به‌کار ببرید.

## نصب و انتخاب شعبه
1. فایل `Vahdat-Desktop-Setup-Win7-to-Win11-v1.6.0-beta.exe` را از ZIP
   خروجی موفق GitHub Actions استخراج و نصب کنید. Python جداگانه لازم نیست.
2. نخستین اجرا: نام، موبایل و رمز دست‌کم ده‌کاراکتری **سوپرمدیر محلی**
   را تعریف کنید. این حساب مخصوص همان رایانه است و حساب سایت نیست.
3. سوپرمدیر از «تنظیمات مرکزی»، شعبه مربوط را انتخاب می‌کند.
4. از پنل `https://autobenzvahdat.ir/admin/vahdat/branches` برای همان
   شعبه **کلید مخصوص همان شعبه** را دریافت و در پنجره مخفی وارد می‌کند.
5. دکمه اتصال را بزند. تنها پس از دریافت فهرست مقصدهای مجاز از مرکز
   امکان صدور بارنامه فعال می‌شود.
6. برای کارکنان حساب مستقل با نقش صدور، انبار، حسابداری یا مدیر شعبه بسازید.
   تنظیمات ارتباطی برای این کاربران نمایش داده نمی‌شود.

## مسیرها
- تهران: فقط آمل، بابل، قائم‌شهر، ساری
- هرکدام از چهار شعبه: فقط تهران
- امکان تعریف مقصد نامجاز در فرم صدور وجود ندارد.

## امنیت و داده
- شناسه و کلید ارتباط در فرم کارکنان نشان داده نمی‌شود.
- کلید در `C:\ProgramData\VahdatUniversal\branch-connection.dpapi`
  با DPAPI مرتبط با **حساب کاربری ویندوز** رمزگذاری می‌شود.
- پوشه داده عملیاتی: `C:\ProgramData\VahdatUniversal\`
  و دیتابیس محلی `vahdat.sqlite3`.
- استفاده با یک حساب ویندوز متفاوت ممکن است مانع رمزگشایی تنظیمات شود.
  برای چند کارمند بهتر است با حساب‌های درون برنامه روی یک حساب ویندوز
  محافظت‌شده کار کنند؛ نسخه نهایی Server 2019 باید از سرویس سیستم استفاده کند.
- فقط مدیر عامل سیستم‌عامل قادر است امنیت خود ویندوز را اداره کند؛
  DPAPI مانع دسترسی مهاجم دارای کنترل کامل همان حساب ویندوز نمی‌شود.
- اولین انتخاب شعبه باید صحیح باشد؛ بعد از ثبت بارنامه، تغییر هویت شعبه
  از داخل برنامه ممنوع است تا سوابق شعب با هم مخلوط نشوند.
- هیچ دیتابیسی از نسخه پایلوت قائم‌شهر یا نسخه قدیمی مرورگری منتقل نمی‌شود.
  نصب جدید با بارنامه شماره **۱** شروع می‌شود.

## محدوده نسخه دسکتاپ بتا
قابل تست: ورود کاربران، صدور، فهرست بارنامه‌ها، ثبت راننده، تحویل بارنامه
به راننده، اسکن/دریافت، وضعیت همگام‌سازی و گزارش مالی خلاصه.
**چاپ سه‌نسخه‌ای A4، گزارش‌های تفصیلی و تسویه‌های کامل هنوز باید
در رابط دسکتاپ بازبینی و تکمیل شوند.** موتور اصلی داده و API موجود در
سورس حفظ شده است ولی همه عملیات در رابط Tk هنوز عرضه نشده‌اند.

## سناریوی تست واقعی
- ابتدا تهران و قائم‌شهر را با کلیدهای جداگانه به مرکز متصل کنید.
- تهران → قائم‌شهر و قائم‌شهر → تهران را با داده ساختگی امتحان کنید.
- بدون اینترنت روی هر شعبه بارنامه ثبت کنید، سپس وصل و صف را بررسی کنید.
- تحویل به راننده، اسکن مقصد و برگشت تأیید را بررسی کنید.
- قبل از استفاده واقعی روی Windows 7 و Windows 11، نصب روی دستگاه‌های
  فیزیکی و چاپگر/بارکدخوان باید آزمایش شود.

## پایان تست و شروع از شماره ۱
نسخه نهایی باید روی Windows Server 2019 با دیتابیس تازه نصب شود.
داده‌های تست را **بکاپ و آرشیو** کنید؛ توکن‌های تست مرکز را باطل کنید و
برای نسخه عملیاتی کلید تازه صادر کنید. دیتابیس آزمایشی را به محیط عملیاتی
منتقل نکنید. برای حذف سوابق تستی **فقط جدول‌های مخصوص سیستم باربری**
و فقط با تأیید و بکاپ جداگانه بررسی شوند؛ بخش رزرو بلیت دست‌نخورده بماند.
